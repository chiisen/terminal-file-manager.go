# 外掛狀態與設計決策（#12）

## 目前可用程度

`internal/plugin` 提供 `Plugin` 介面、程式內註冊／查詢／執行及示範外掛。`LoadPlugins()` 只建立 `~/.config/gofm/plugins` 並列出子目錄，不載入程式、腳本或 `.so`；命令列與 TUI 都沒有外掛入口。將檔案放入此目錄不會使它生效。

## 決策：採用外部程序，暫不實作動態載入

Windows 與 Linux 均為專案目標，因此後續使用 `os/exec` 啟動外掛程序及 stdin/stdout JSON 協定。與原生 Go plugin 相比，程序呼叫有啟動與序列化成本，但不要求外掛與主程式使用相同 Go 工具鏈，程序崩潰也不直接終止 TUI。

Go 官方 [plugin 文件](https://pkg.go.dev/plugin)列出平台、race detector 及工具鏈／共同依賴一致性的限制。原生 `.so` 方案未涵蓋 Windows，不適合作為本專案預設。純程式內註冊雖最簡單，但必須重新編譯主程式才能擴充，保留作測試與內建功能用途。

## 後續協定與信任邊界

- 每個外掛目錄以 `manifest.json` 宣告唯一名稱、協定版本 `1`、可執行檔及固定參數。相對路徑只能指向該目錄內的檔案；腳本須明確指定直譯器，不經 shell 拼接指令。
- 一次執行只交換一份 JSON：stdin 為 `{"version":1,"args":["..."],"cwd":"...","selected":["..."]}`；stdout 為 `{"version":1,"output":"..."}`。stderr 作診斷，不混入 JSON；回傳內容當純文字呈現，不允許控制終端跳脫序列。
- 退出碼非零、無效 JSON、不支援版本及逾時一律視為失敗，不回報成功。預設單次 30 秒、輸出上限 1 MiB；TUI 背景執行並顯示執行／完成／失敗。
- 使用者明確啟用指定外掛後才可執行；掃描目錄不得自動啟動程序。只傳必要路徑與參數，避免繼承 SSH 密碼等敏感設定。
- 外掛擁有使用者程序權限，並非沙箱。啟用前必須信任程式來源；不提供自動下載或安裝。

以上為後續實作規格，現有 `LoadPlugins()` 尚未提供這些能力。

## 後續實作範圍與驗收

1. manifest 解析、名稱／路徑／版本驗證與明確啟用設定。
2. 外部程序 adapter、JSON 協定、逾時取消、輸出限制與錯誤處理。
3. TUI 明確選擇與執行入口；程序工作不得阻塞事件迴圈。
4. Windows／Linux 可執行測試外掛，覆蓋成功、非零退出、逾時、超量輸出、畸形 JSON、路徑越界及未啟用不執行。
